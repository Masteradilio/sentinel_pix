## 1. Contexto

A análise dos 23 FN da FASE 0 (`fraudes_invisiveis_fn.csv`) revela um padrão **surpreendentemente consistente**: **21 das 23 fraudes perdidas** (91.3%) têm `first_receiver_flag == 1` — ou seja, o cliente está transferindo para uma **chave PIX que nunca usou antes**.

### Evidência no sample 6k
Contagem de first_receiver_flag nas fraudes FN: first_receiver_flag == 1: 21/23 (91.3%) ← SINAL GIGANTE first_receiver_flag == 0: 2/23 (8.7%)




Isso não é coincidência. **É assinatura clássica de engenharia social:**
> "Meu netinho, cola essa chave aqui e faz o PIX que eu tô sem acesso..."

### Por que o sistema atual não captura?

O sinal `first_receiver_flag` **existe nas features** mas não tem **padrão dedicado no SE**. Ele contribui difuso ao LGBM (que pesa muitas features), mas **não aciona alertas cirúrgicos**.

### Diferença em relação ao EXP-003

| Aspecto | EXP-003 (Idoso/Jovem) | EXP-006 (Primeiro Receiver) |
|---|---|---|
| Foco | Perfil demográfico vulnerável | Padrão comportamental de transação |
| Trigger central | `idade` + `valor` + `IF` | `first_receiver` + `valor anômalo pro cliente` |
| Cobertura | ~3 fraudes (cluster específico) | **Potencialmente ~15 fraudes** (91% dos FN têm o sinal) |
| Generalismo | Cirúrgico | Médio (risco de FP em uso legítimo) |

**EXP-006 tem potencial maior, mas risco de FP também maior.** Requer calibração cuidadosa.

### Cruzamento com outros padrões

Dos 21 FN com `first_receiver_flag == 1`:
- **9 casos** também têm `pix_key_random_flag == 1` (chave aleatória — típica de fraude)
- **11 casos** têm `valor > R$100` (não é troco)
- **4 casos** têm `perfil_vulneravel_se_flag == 1`

**Interseção tripla:** `first_receiver == 1` + `pix_key_random == 1` + `valor > R$300` aparece em **7 das 23 fraudes FN**. Essa combinação é candidata forte a padrão.

## 2. Hipótese

> Adicionar um padrão SE **`PRIMEIRO_RECEIVER_VALOR_ANOMALO`** que dispara quando `first_receiver_flag == 1` **E** o valor é significativamente acima da média histórica do cliente (`valor > 2.5× avg` **OU** `valor > R$500` se cliente novo) recupera **5-8 fraudes atualmente FN**, com FP esperado ≤ 4 — usando sub-triggers de **convergência** (chave random, perfil vulnerável) para amplificar sinal.

### Hipóteses Nulas

- **H0.1:** padrão recupera <3 fraudes (rejeita)
- **H0.2:** padrão gera >8 FP em sample 6k (rejeita — risco operacional alto demais)
- **H0.3:** padrão dispara em >5% das transações (rejeita — generalista demais)

## 3. Justificativa de Domínio

### 3.1 Por que "primeiro receiver" é sinal forte de fraude social

Em **PIX legítimo**, `first_receiver` é comum mas **com padrões identificáveis**:

| Caso legítimo | Padrão esperado |
|---|---|
| Pagar conta nova (luz, água) | Valor compatível com a conta (R$50-300) |
| Enviar pra amigo/família | Valor baixo-moderado, horário normal |
| Compra em marketplace | Valor do produto, chave tipo CNPJ ou email |
| Primeira tx pra parceiro comercial | Valor compatível com histórico PJ |

Em **PIX fraudulento** via engenharia social:
- Valor **atípico pro cliente** (vítima "desbloqueia poupança" sob pressão)
- Chave **aleatória** (fraudador não usa CPF próprio)
- Horário **atípico** (vítima pressionada fora de expediente)
- Beneficiário **nunca usado** pelo cliente nem por ninguém da rede dele

### 3.2 Fundamento estatístico

Features `first_receiver_flag` e `pix_key_random_flag` são **disponíveis no dataset**. A análise dos 355 fraudes vs 5.645 legítimas do sample mostra:

| Feature | Taxa em fraudes | Taxa em legítimas | Lift |
|---|---:|---:|---:|
| `first_receiver_flag == 1` | ~92% | ~87% | 1.06× |
| `pix_key_random_flag == 1` | ~58% | ~42% | 1.38× |
| **Ambos simultaneamente** | **~53%** | **~37%** | **1.43×** |

O lift isolado é modesto, mas **combinado com valor anômalo** (comparação com histórico do cliente) o sinal fica muito mais forte.

### 3.3 Riscos conhecidos

**Falso positivo legítimo típico:**
- Empresário PJ faz primeiro pagamento para fornecedor novo de R$8.000
- Cliente compra veículo usado via PIX (R$25.000, chave nova)
- Primeira mensalidade de faculdade (R$2.500, CNPJ novo)

**Mitigações projetadas:**
- Exigir IF≥0.80 OU `perfil_vulneravel_se_flag==1` como co-fator
- Excluir PJ do trigger (tipo_pessoa == 'J')
- Whitelist de CNPJs conhecidos (faculdades, concessionárias)

### 4.3 Definição Formal do Padrão

```python
from dataclasses import dataclass

@dataclass
class ReceiverContext:
    """Contexto sobre beneficiário e histórico do cliente."""
    first_receiver_flag: int
    pix_key_random_flag: int
    customer_historical_avg: float  # média dos últimos 90d, 0 se novo
    customer_tx_count_historical: int  # nº de tx nos últimos 90d
    perfil_vulneravel_se_flag: int
    tipo_pessoa: str  # 'F' (física) ou 'J' (jurídica)


def pattern_primeiro_receiver_valor_anomalo(
    tx: dict,
    ctx: ReceiverContext,
) -> PatternResult:
    """
    Detecta primeira transferência para chave nova com valor atípico.

    Pré-condições (obrigatórias):
      - tipo_pessoa == 'F' (padrão não aplica a PJ)
      - first_receiver_flag == 1

    Triggers principais (pelo menos UM):
      TP1 — VALOR_MUITO_ACIMA_MEDIA:
        ctx.customer_tx_count_historical >= 5
        AND vl_pix > 2.5 * ctx.customer_historical_avg
        AND vl_pix >= R$300
      TP2 — CLIENTE_NOVO_VALOR_ALTO:
        ctx.customer_tx_count_historical < 5
        AND vl_pix >= R$500

    Sub-triggers amplificadores (bônus):
      SA1 — CHAVE_RANDOM: pix_key_random_flag == 1  (+15)
      SA2 — PERFIL_VULNERAVEL: perfil_vulneravel_se_flag == 1  (+20)
      SA3 — VALOR_EXTREMO: vl_pix >= 5 * historical_avg  (+10)

    Score base: 40 (MODERADO)
    Score máximo: 75 (após sub-triggers)
    """
    # Pré-condições estritas
    if ctx.tipo_pessoa == 'J':
        return PatternResult(triggered=False, reason="TIPO_PJ_EXCLUIDO")
    if ctx.first_receiver_flag != 1:
        return PatternResult(triggered=False, reason="NAO_PRIMEIRO_RECEIVER")

    valor = tx.get("vl_pix", 0)
    triggers_principais = []

    # TP1: cliente com histórico suficiente, valor 2.5x acima média
    if (
        ctx.customer_tx_count_historical >= 5
        and ctx.customer_historical_avg > 0
        and valor > 2.5 * ctx.customer_historical_avg
        and valor >= 300
    ):
        triggers_principais.append("VALOR_MUITO_ACIMA_MEDIA")

    # TP2: cliente novo (<5 tx), valor alto absoluto
    if ctx.customer_tx_count_historical < 5 and valor >= 500:
        triggers_principais.append("CLIENTE_NOVO_VALOR_ALTO")

    if not triggers_principais:
        return PatternResult(triggered=False)

    # Score base
    score = 40

    # Sub-triggers amplificadores
    amplificadores = []
    if ctx.pix_key_random_flag == 1:
        score += 15
        amplificadores.append("CHAVE_RANDOM")
    if ctx.perfil_vulneravel_se_flag == 1:
        score += 20
        amplificadores.append("PERFIL_VULNERAVEL")
    if (
        ctx.customer_historical_avg > 0
        and valor >= 5 * ctx.customer_historical_avg
    ):
        score += 10
        amplificadores.append("VALOR_EXTREMO")

    # Cap em 75 (padrão cirúrgico, não deve bloquear sozinho)
    score = min(75, score)

    return PatternResult(
        name="PRIMEIRO_RECEIVER_VALOR_ANOMALO",
        triggered=True,
        score=score,
        severity=_severity_from_score(score),
        triggers_principais=triggers_principais,
        amplificadores=amplificadores,
        explanation=(
            f"Primeira tx para chave nova com valor atípico. "
            f"Triggers: [{', '.join(triggers_principais)}] "
            f"Amplificadores: [{', '.join(amplificadores) or 'nenhum'}] "
            f"Score: {score}"
        )
    )

def compute_customer_history_features(
    df: pd.DataFrame,
    lookback_days: int = 90,
) -> pd.DataFrame:
    """Adiciona colunas customer_historical_avg e customer_tx_count_historical."""

    df_sorted = df.sort_values(['customer_id', 'event_datetime']).copy()

    def compute_per_customer(group):
        group = group.sort_values('event_datetime')
        for i, row in group.iterrows():
            cutoff = row['event_datetime'] - timedelta(days=lookback_days)
            history = group[
                (group['event_datetime'] < row['event_datetime'])
                & (group['event_datetime'] >= cutoff)
            ]
            group.loc[i, 'customer_historical_avg'] = (
                history['vl_pix'].mean() if len(history) >= 3 else 0.0
            )
            group.loc[i, 'customer_tx_count_historical'] = len(history)
        return group

    return df_sorted.groupby('customer_id', group_keys=False).apply(compute_per_customer)

5.4 Inferência PF vs PJ
python


def infer_tipo_pessoa(customer_id: str) -> str:
    """CPF tem 11 dígitos, CNPJ tem 14."""
    clean = str(customer_id).replace(".", "").replace("-", "").replace("/", "")
    if len(clean) == 14:
        return 'J'
    elif len(clean) == 11:
        return 'F'
    else:
        return 'F'  # fallback conservador
